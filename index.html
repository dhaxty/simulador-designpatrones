Problema: sistema de pedidos de una cafetería

Una cafetería vende café a S/ 5. Cada bebida permite consultar su descripción y precio.

Los clientes pueden agregar leche por S/ 2 y chocolate por S/ 3. Estos extras deben poder combinarse y agregarse sucesivamente, sin modificar la clase del café ni crear una clase para cada combinación posible.

Diseñe una solución utilizando el patrón Decorator. Represente sus clases, atributos, métodos y relaciones en un diagrama UML.

Diagrama UML

El diagrama usa Mermaid y requiere conexión a Internet para cargar la biblioteca.

¿Por qué están esas flechas?

1. Cafe → Bebida: implementación

Es una línea discontinua con un triángulo vacío apuntando a Bebida. Representa: 

class Cafe implements Bebida

Cafe debe implementar getDescripcion() y getPrecio(), porque están declarados en Bebida. El triángulo apunta a la interfaz que se implementa.

2. BebidaDecorator → Bebida: implementación

También es una línea discontinua con un triángulo vacío apuntando a Bebida. Representa: 

abstract class BebidaDecorator implements Bebida

Esto permite utilizar un decorador donde se espera una Bebida, igual que ocurre con Cafe.

3. ConLeche y ConChocolate → BebidaDecorator: herencia

Son líneas continuas con triángulos vacíos apuntando a BebidaDecorator. Representan: 

class ConLeche extends BebidaDecorator
class ConChocolate extends BebidaDecorator

Ambas clases heredan la referencia a la bebida y el comportamiento del decorador base. Después redefinen los métodos para agregar su extra. El triángulo apunta a la clase padre.

4. BebidaDecorator → Bebida: asociación

Es una línea continua con una flecha simple hacia Bebida. Representa el atributo: 

protected Bebida bebida;

Cada decorador guarda una referencia a la bebida que envuelve. El número 1 indica que cada decorador del modelo envuelve una bebida.

Apunta a Bebida porque el objeto envuelto puede ser un Cafe o cualquier otro decorador. Así se pueden combinar los extras.

Usamos una asociación simple: el enunciado no establece reglas de propiedad exclusiva ni de ciclo de vida que requieran un rombo de composición.

¿Por qué hay dos relaciones entre BebidaDecorator y Bebida?

Porque representan cosas diferentes: BebidaDecorator es una Bebida al implementar su interfaz y, además, contiene una referencia a otra Bebida. Esa combinación permite construir la cadena.

Ejemplo de combinación

Bebida pedido =
    new ConChocolate(
        new ConLeche(
            new Cafe()
        )
    );

Chocolate envuelve a leche, y leche envuelve al café. El precio se calcula como 5 + 2 + 3 = S/ 10.

Símbolos utilizados

  • +: miembro público.
  • #: miembro protegido.
  • «interface»: interfaz.
  • «abstract»: clase abstracta.
  • Triángulo vacío + línea discontinua: implementación de una interfaz.
  • Triángulo vacío + línea continua: herencia de una clase.
  • Flecha simple + línea continua: asociación navegable.
